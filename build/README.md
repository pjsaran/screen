# build

Every script that turns the source into something you can install, and every gate
that stands between the two. All PowerShell 7 (`pwsh`), all idempotent, all loud on
failure.

Nothing here is optional tooling you might or might not have installed: FFmpeg and
Inno Setup are fetched, pinned, and checksum-verified by the scripts themselves.

## The one you will use

```powershell
pwsh build/build.ps1                        # gates, build, test
pwsh build/build.ps1 -Publish -Installer    # + self-contained publish + installer
pwsh build/new-release.ps1 -Bump minor      # + version, tag, GitHub release
```

## What each script is for

| Script | Owns |
|---|---|
| `build.ps1` | The pipeline: tools, licence gate, formatting, warnings-as-errors build, tests, publish, installer. Start here. |
| `fetch-ffmpeg.ps1` | Downloads the FFmpeg pinned in `ffmpeg.lock.json`, verifies its SHA-256, and **interrogates the binary** to prove it really has `ddagrab` and the encoders Captr probes for. Writes `capabilities.json`. |
| `check-licenses.ps1` | The licence gate. Fails on any package licence outside the allow-list, and on drift between reality and the committed `licenses/THIRD-PARTY.md`. |
| `make-icons.ps1` | Draws the application and tray `.ico` files from code, so the icon design is reviewable and adjustable without a graphics tool. The results are committed; run this only when the design changes. |
| `make-installer.ps1` | Compiles `installer/captr.iss` with a pinned, hash-checked Inno Setup (signing the installer and uninstaller when signing is configured), verifies every shipped file's signature, and writes `SHA256SUMS.txt`, `release.json`, `signature-report.json` and the symbols zip. |
| `Sign-Artifacts.ps1` | Authenticode signing of every shipped file that no trusted publisher already signed: PFX, certificate store, or Azure Artifact Signing, chosen from the environment (`CAPTR_SIGN_*`, see [releasing](../docs/developer-guide/releasing.md)). SHA-256 with an RFC 3161 timestamp. `-DryRun` shows the plan with no certificate. Unconfigured, it warns and the build still succeeds; `-Require` (releases) makes that a failure. |
| `Verify-Signatures.ps1` | Fails on any shipped file that is unsigned, untimestamped, or signed by the wrong publisher. |
| `sign.ps1` | Kept only so old command lines work; forwards to `Sign-Artifacts.ps1`. |
| `set-version.ps1` | The only way a version number is ever changed. Writes `Version.props`; everything else derives from it. |
| `new-release.ps1` | The whole release: version, build, test, package, verify, tag, push, GitHub release with the installer attached. Refuses to start from a dirty tree, or without signing configured (unless `-AllowUnsigned`). |
| `create-github-repo.ps1` | One-time bootstrap: create the repository on GitHub, add it as `origin`, push. |
| `verify-install.ps1` | Post-install verification on a real machine: binaries and signatures, the CLI on PATH, then a real short recording that must land correctly named at a destination. The recording runs under a data root of its own, so the person's settings are never touched. |
| `tools/normalise-line-endings.ps1` | Puts the tree back to UTF-8-without-BOM and CRLF. Run it after any bulk edit; `dotnet format` fails the build otherwise. |

## Other files here

| | |
|---|---|
| `ffmpeg.lock.json` | The FFmpeg pin: repository, dated release tag, asset, SHA-256, and the capabilities the fetch asserts. See [upgrading FFmpeg](../docs/developer-guide/upgrading-ffmpeg.md). |
| `installer/captr.iss` | The Inno Setup script. Every SPEC §11 installer behaviour is in here, each with a comment saying which. |
| `installer/version.iss` | Generated by `make-installer.ps1` from `Version.props`, and not tracked by git. Never edit it. |
| `signing.lock.json` | The signing pins: `signtool` and Artifact Signing packages with their SHA-512, the timestamp servers in order of preference, and which publishers' signatures are trusted as they are. |
| `licenses/THIRD-PARTY.md` | The committed licence report the gate compares against. Regenerate and commit it whenever a package is added. |

## Two rules

**Never write a version number outside `Version.props`.** Assembly versions, the
installer's version and file name, and the build identity all derive from it.

**Never pin FFmpeg to a rolling tag.** A rolling tag means the bytes change without
the pin changing, which defeats the checksum entirely. Always a dated
`autobuild-*` release.

## If the build fails on a machine you copied the repo to

Symptom: step 1 prints `File ...\dotnet-tools.json came from another computer and
might be blocked`, and the licence gate then reports that `nuget-license` produced
no output. Cause: the repo arrived as a zip or USB copy, so Windows tagged every
file "from the internet" (Mark of the Web), and the .NET SDK refuses to read a
tagged tool manifest. `build.ps1` now unblocks the manifest itself; if you still hit
it, run this once from the repo root and rebuild:

```powershell
Get-ChildItem -Recurse -File | Unblock-File
```

A `git clone` never carries the tag, so prefer cloning over copying.

A related fresh-machine symptom: a wall of `Failed to get the project assets file`
stack traces from the licence gate. That means no `obj\project.assets.json` exists
yet. `check-licenses.ps1` now runs `dotnet restore` itself before the tool, so this
should not recur; if it does, run `dotnet restore Captr.slnx` and rebuild.

Full detail: [building](../docs/developer-guide/building.md) and
[releasing](../docs/developer-guide/releasing.md).
